# Architecture

## Compiler pipeline

```
Source (.myl)
  -> Flex lexer        (src/lexer.l)
  -> Bison parser      (src/parser.y)  -> builds the AST
  -> Semantic analysis (src/semantic.cpp)
  -> LLVM IR generation(src/ast.cpp + src/codegen.cpp)
  -> LLVM IR verification
  -> Optional optimization (legacy FunctionPassManager)
  -> Native object code -> linked executable (cc -no-pie)
```

The CLI/driver orchestrates the stages (`src/main.cpp`, `src/driver.cpp`).

## Modules

| File | Responsibility |
|------|----------------|
| `src/lexer.l` | Tokenization, string escapes, comments, line/column tracking. |
| `src/parser.y` | Grammar, operator precedence, AST construction, syntax errors. |
| `src/frontend.cpp` | Wires the Flex buffer to `yyparse`; public `parseSource`/`tokenize`. |
| `include/myl/ast.hpp`, `src/ast.cpp` | AST node definitions and their LLVM `codegen` methods. |
| `include/myl/semantic.hpp`, `src/semantic.cpp` | Scopes, name resolution, type/return/argument checking. |
| `include/myl/codegen.hpp`, `src/codegen.cpp` | LLVM context/module/IRBuilder, target machine, emission. |
| `include/myl/driver.hpp`, `src/driver.cpp` | High-level compile modes and diagnostics. |
| `include/myl/frontend.hpp` | Frontend public API and `TokenInfo`. |

## Frontend (Flex + Bison)

- The lexer is generated by Flex; the parser by Bison. CMake generates both
  into `${CMAKE_BINARY_DIR}/generated`, so no generated source is committed.
- `myl::parseSource(source, filename, errors)` installs the source into the
  scanner with `yy_scan_string`, runs `yyparse`, and returns a `Program`.
- The Bison token names `Identifier`, `IntegerLiteral`, `FloatLiteral`,
  `StringLiteral` intentionally share names with AST classes; inside the
  `myl` namespace the token constants are referenced as `::Identifier`, etc.
- The semantic value union (`%union`) holds only trivial types (pointers,
  enums, `int`, `long long`, `double`). `myl::Type` is passed as a
  `TypeKind` integer and converted with `to_type()`; this keeps `YYSTYPE`
  trivially default-constructible, which the C parser relies on.

## AST and ownership

- `Expr`, `Stmt`, and `Decl` are polymorphic bases owning their `codegen`
  method; children use `std::unique_ptr` (`ExprPtr`, `StmtPtr`, `DeclPtr`).
- The parser builds nodes from raw pointers held in the Bison union, then
  transfers ownership into `unique_ptr`s via helpers (`take_stmts`,
  `take_exprs`, `take_decls`, `wrap`). Temporary raw `std::string*` values are
  deleted after being copied into nodes.
- `CodeGenContext` owns the LLVM context, module, IR builder, and pass manager
  (RAII, no global mutable compiler state).

## Semantic analysis

- Lexically nested `Scope` objects track symbols (`Variable`, `Function`,
  `Parameter`) with type, mutability, and initialization.
- Checks performed: undefined identifiers/functions, redefinition, immutable
  assignment, condition types (`if`/`while` must be `bool`), arithmetic and
  comparison operand types, function argument count/types, return type, and
  presence of a `return` in non-void functions.
- `print` is registered as a built-in that accepts any value. The arithmetic
  built-ins `jodo`/`ghatao`/`guna`/`bhaag` are reserved names whose types are
  computed inline (numeric operands, `float` if either side is `float`).
- Top-level statements (`StmtDecl`) are collected by the parser and wrapped
  into an implicit `main`, so script-style programs become ordinary functions
  before semantic analysis runs.

## LLVM decisions

- LLVM **15** (C++ API), matched to the `llvm-15-dev` package on Ubuntu 22.04.
- `int` = `i64`, `float` = `double`, `bool` = `i1`, `string` = `i8*`.
- IR is verified with `llvm::verifyModule` before emission; invalid IR is
  never accepted as success.
- Optimization uses the legacy `FunctionPassManager` (instruction combining,
  reassociate, GVN, CFG simplification).
- Targets use `Reloc::Static` and are linked with `cc -no-pie`.
- `print` lowers to `printf` (`%lld`, `%g`, `%d`, `%s`), so no separate runtime
  library needs to be shipped.

## CLI and diagnostics

- `check` runs lexer → parser → semantic analysis, emitting no output file.
- `emit-ir` writes verified LLVM IR.
- `build` emits an object file and links a native executable.
- `run` builds, executes, and propagates the program's exit status.
- Compiler diagnostics go to `stderr`; program output goes to `stdout`.

## Adding a feature

1. Add any new tokens in `src/lexer.l` and `%token`s in `src/parser.y`.
2. Add/extend AST nodes in `include/myl/ast.hpp` and their `codegen` in `src/ast.cpp`.
3. Add semantic rules in `src/semantic.cpp`.
4. Add a unit test and an example program; update the integration tests.
5. Build and test in Docker; update `docs/LANGUAGE_SPEC.md` and the appendix in
   `AGENTS.md`. Never document a feature as working before it is verified.
